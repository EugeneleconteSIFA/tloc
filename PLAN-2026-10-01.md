# Plan du 1er octobre — travail en autonomie

Décidé avec Eugène le 30 septembre au soir. Ce fichier dit **quoi faire, dans quel ordre,
et jusqu'où aller sans lui demander**. Pour l'histoire, `STORY.md` fait foi ; pour les
règles de fabrication, `GAME_DESIGN_BRIEF.md` ; pour les règles de la maison, `CLAUDE.md`.

## Ce qu'Eugène autorise sans redemander

- **Publier sur le DEV** (tloc-dev.kernse.fr) dès qu'un lot est vérifié, **si le contrôle
  automatique passe** (étape 1). La **prod** ne se touche jamais : c'est lui, par le bouton
  « Promouvoir ».
- **Déplacer** des fichiers pour ranger le dépôt, chemins mis à jour et jeu revérifié.
  **Supprimer : jamais sans lui.** On lui prépare une liste, il coche.
- Tout le reste des règles de `CLAUDE.md` tient toujours (pas de checkout/reset/pull,
  éditer en place, vérifier en rendu, budget de chargement).

## L'ordre de travail

### 1. Les garde-fous — rendre les règles mécaniques

Aujourd'hui les non-négociables ne sont que du texte. Ils deviennent des contrôles.

- **`publier-dev.sh` refuse d'envoyer** si l'un échoue :
  1. `node --check` sur chaque module modifié ;
  2. démarrage headless de la citadelle sans `pageerror` (et d'un intérieur) ;
  3. `bancs/charge.mjs` : **médiane de 3 passes**, somme des étapes ≤ 17 s, poids réseau
     plafonné (40–42 Mo aujourd'hui : le plafond est à fixer sur la mesure du matin, au calme).
  Le script n'ajoute plus tout le dossier (`git add .`) : il montre les fichiers et
  n'envoie que ceux du lot — le 30, il a failli embarquer le travail d'une autre session.
- **Hooks Claude Code** (`.claude/settings.json`, via le skill `update-config`) :
  - bloquer `git checkout`, `git reset`, `git pull`, `git stash`, `git clean` ;
  - bloquer toute écriture dans un fichier listé dans **`.claude/verrous.txt`** — la liste
    qu'Eugène remplit le matin (règle 2 de `CLAUDE.md`, rendue automatique).
- Attention à `charge.mjs` : il écrase le relevé du jour (`charge-<date>.json`). Lui donner
  une étiquette en argument avant de s'en servir dans le contrôle.

**Fini quand** : une publication volontairement cassée (erreur de syntaxe, puis budget
dépassé) est refusée, et une publication propre passe.

### 2. Le rangement — seul, sans autre session active

Un déplacement casse les chemins des autres sessions : vérifier avec `list_sessions`
qu'aucune autre session TLOC ne tourne avant de commencer.

- Les notes vers **`docs/`** : `BRIEF-*`, `NOTE-*`, `REPONSE-*`, `CONTEXT.md`,
  `ORCHESTRATION.md`, `PROMPTS-SESSIONS.md`, `SCENARIO.md`, `DIALOGUES-ACTE1.md`,
  `GAME_DESIGN_BRIEF.md`. Restent à la racine : `CLAUDE.md`, `PROMPT-REPRISE.md`,
  `STORY.md`, `README.md`. Mettre à jour les renvois (`CLAUDE.md`, `PROMPT-REPRISE.md`).
- Les relevés de banc (`*.json`, `*.png`, `*.cpuprofile`) vers **`bancs/resultats/`** ;
  les scripts restent dans `bancs/` (adapter leurs chemins d'écriture).
- **Inventaire, sans rien supprimer** : ce qui n'est chargé par aucune page (sources
  d'assets, `verdant_trail/`, `hidden_alley/`, `Universal Animation Library…`, outils à
  usage unique, `Claude outputs/`). Une liste à cocher pour Eugène, avec la taille de chaque ligne.
- **La musique hors d'`engine.js`** : la correspondance zones → ambiances (`ambianceDe`)
  est du contenu de niveau posé dans le bien commun (contraire à `ORCHESTRATION.md`, règle 3).
  `engine.js` garde le lecteur ; chaque niveau dit son ambiance.
- `serveur/deploiement/exclure.txt` : vérifier qu'aucun déplacement ne fait partir sur le
  VPS ce qui n'y allait pas.

**Fini quand** : racine lisible, jeu qui démarre (citadelle + intérieurs), banc inchangé,
contrôle de l'étape 1 qui passe, liste de suppressions remise à Eugène.

### 3. Le mobile — iPhone (Safari) et Android (Chrome), solo ET multi

**Les commandes** (≈ 2 jours) :
- détection tactile (`pointer: coarse`) ; rien ne change au clavier ;
- joystick virtuel à gauche, caméra au glisser à droite (remplace le pointer lock) ;
- boutons : épée, roulade, saut, action ; une roue pour le reste (carte, journal, poche,
  arc, boire, manger) — branchée sur `TOUCHES`, pas un système à côté ;
- menus, dialogues et cinématiques au toucher ; en multi, un clavier à l'écran pour le chat ;
- plein écran et paysage imposé ; interface lisible à 375 px de haut.

**La tenue sur téléphone** (le vrai risque) :
- mémoire JS mesurée à 1,5 Go le 30 : Safari iOS tue l'onglet vers 1–1,5 Go. Ajouter la
  mémoire au banc, puis une **qualité mobile** : textures KTX2 (`outils_ktx2.mjs`), ombres
  coupées, distance d'affichage réduite, moins d'herbe ;
- vérifier en émulation (Playwright, profil iPhone/Android, tactile) ;
- **la vérité vient du vrai téléphone d'Eugène** sur le dev : lui laisser un protocole
  court (quoi ouvrir, quoi regarder, quoi nous dire).

### 4. Ensuite — l'acte I d'après `STORY.md`

Dans l'ordre du récit, en commençant par le prologue (la fête des géants). Pour chaque scène :
découpage écrit (plans, caméra, durée, réplique) → planche d'images rendues en headless →
validation d'Eugène → la quête codée. Les cinématiques existent déjà (`cutscene`, plan par
plan : `cam`, `at`, `cam2`, `at2`, `dur`).

## Rendre compte

Un point bref toutes les ~15 min sur les longs chantiers. En fin de lot : ce qui est
fait, ce qui est vérifié et comment, ce qui ne l'est pas, ce qui est publié sur le dev.
Ce qu'on voit à améliorer se note dans `PROMPT-REPRISE.md`.
